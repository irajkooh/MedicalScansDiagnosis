# How to Keep a Hugging Face Space Always Alive

## The Problem

Free HF Spaces sleep after **48 hours of inactivity**. When asleep:
- The container shuts down
- Users get a "Starting..." screen with a 1-5 minute cold start
- For this app: model re-download (~8.6GB) + pipeline load adds several more minutes

The "Sleep time settings" in Space Settings is **grayed out on free CPU tier** — you cannot disable sleep from the UI.

---

## Why Self-Ping Inside the App Doesn't Work

An earlier approach added APScheduler inside `app.py` to ping the Space URL every 30 minutes from within the app itself:

```python
# THIS APPROACH WAS REMOVED — unreliable
from apscheduler.schedulers.background import BackgroundScheduler
import requests

scheduler = BackgroundScheduler()
scheduler.add_job(lambda: requests.get(SPACE_URL), "interval", minutes=30)
scheduler.start()
```

**Why it fails:**
- If the app crashes (e.g. out of memory), the scheduler dies with it
- Nothing external wakes the app back up after a crash
- On free CPU with an 8.6GB model loaded, memory pressure is a real risk
- Result: app eventually sleeps and stays asleep until a human visits

---

## The Solution: External Pinger via GitHub Actions

The reliable approach is an **external service** that pings the Space URL on a schedule, completely independent of the app. Even if the app crashes and HF restarts it, the next ping from outside will wake it up automatically — no human needed.

### What Was Added

A GitHub Actions workflow at `.github/workflows/keep-alive.yml`:

```yaml
name: Keep HF Space Alive

on:
  schedule:
    - cron: "*/20 * * * *"  # every 20 minutes
  workflow_dispatch:         # allow manual trigger

jobs:
  ping:
    runs-on: ubuntu-latest
    steps:
      - name: Ping HF Space
        run: curl -s -o /dev/null -w "%{http_code}" https://irajkoohi-medicalscansdiagnosis.hf.space
```

**How it works:**
- GitHub's servers run this job every 20 minutes, 24/7
- It sends an HTTP GET request to the Space URL
- HF sees the request as activity → resets the idle timer → Space stays awake
- 20 minutes is well within the 48-hour sleep threshold
- If the app was sleeping, the ping wakes it up within 20 minutes maximum
- Completely free on GitHub's free tier (2,000 minutes/month, this uses ~72/day)

### What Was Removed from `app.py`

The following were removed since they are no longer needed:

```python
# REMOVED imports
import requests
from apscheduler.schedulers.background import BackgroundScheduler

# REMOVED code (was at bottom of app.py)
SPACE_URL = "https://irajkoohi-medicalscansdiagnosis.hf.space"

def self_ping():
    try:
        requests.get(SPACE_URL, timeout=10)
        print("✓ Self-ping successful")
    except Exception as e:
        print(f"✗ Self-ping failed: {e}")

scheduler = BackgroundScheduler()
scheduler.add_job(self_ping, "interval", minutes=30)
scheduler.start()
```

`apscheduler` was also removed from `requirements.txt`.

## Setup Steps (One-Time)

1. **Create a GitHub repo** for this project (already done: `github.com/irajkooh/MedicalScansDiagnosis`)
2. **Push the workflow file** — the `.github/workflows/keep-alive.yml` file must be committed and pushed to GitHub
3. **Trigger the first run manually**:
   - Go to `github.com/irajkooh/MedicalScansDiagnosis/actions`
   - Click **"Keep HF Space Alive"**
   - Click **"Run workflow"** → **"Run workflow"** (green button)
4. GitHub will now run it automatically every 20 minutes forever

## Keeping GitHub and HF Space in Sync

This project now has **two remotes**:

| Remote | URL | Purpose |
|--------|-----|---------|
| `space` | `https://huggingface.co/spaces/irajkoohi/MedicalScansDiagnosis` | Deploys the app |
| `github` | `https://github.com/irajkooh/MedicalScansDiagnosis` | Hosts the keep-alive workflow |

When deploying changes, push to **both**:

```bash
git push space main    # deploys app to HF Space
git push github main   # keeps GitHub in sync
```
